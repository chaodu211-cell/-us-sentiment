# 美股情绪温度计 — 离线运行包

这个项目**不依赖 Claude、不依赖任何大模型、不需要 API key**。
整条流水线是纯 Python + pandas/numpy，数据全部来自公开免费端点。
只要你的机器能跑 Python、能上网，它就能一直跑下去。

## 零、最省事的用法：下载 → 双击

不想碰终端的话，这条就够了：

1. GitHub 上点 **Code → Download ZIP**，解压
2. **右键点** `更新并打开.command` → **打开** → 在弹窗里再点一次「打开」
3. 等它跑完，网页会自动弹出来

之后每次想更新，**直接双击** `更新并打开.command` 就行，不用再右键。

脚本会自己：找 Python → 缺 pandas/numpy/scipy 就装 → 下载最新行情 → 重算温度
→ 渲染网页 → 打开。出错时把原因留在窗口里，不会一闪而过。

| 文件 | 什么时候用 |
|---|---|
| `更新并打开.command` | **日常用这个**。增量更新，几十秒 |
| `完整更新并打开.command` | 很少用。怀疑数据有问题时强制重下十年历史 |

### 三个必须知道的点

**① 第一次为什么要右键→打开，不能直接双击**

从网上下载的文件都带 macOS 的隔离标记（`com.apple.quarantine`），直接双击会被
Gatekeeper 拦下，提示"未受信任的开发者"或者干脆没反应。右键→打开是系统提供的
放行方式，**只需要做这一次**——脚本跑起来后会把同目录其余文件的标记一并清掉。

**② 第一次要等几分钟，之后就快了**

`raw/`（十年原始数据，约 43MB / 540 个 CSV）**不在 git 仓库里**——它每天都会被
整体重写，提交进去会让仓库历史无限膨胀且无法回收。所以你下载的 ZIP 里没有它，
第一次运行必须把 531 只标的的十年日线整个下下来，3–10 分钟。以后每次只下增量。

**③ 双击完全没反应？**

极少数解压工具会丢掉可执行权限。在终端里跑一次这个就好（只需一次）：

```bash
cd 你解压出来的文件夹
chmod +x *.command
```

## 一、五分钟跑起来

```bash
# 1. 装依赖（只有三个）
pip install pandas numpy scipy

# 2. 跑一次完整流程
python3 daily_refresh.py          # 首次用这个（全量）
python3 daily_refresh.py --fast   # 以后日常用这个（增量，快 10 倍以上）

# 3. 用浏览器打开生成的 dashboard.html
```

**全量 vs 增量**：全量每只票重下 10 年日线，531 只 ≈ 134MB，跨境链路上要十分钟；
增量只下最近半年再并回本地，约 7MB，通常几十秒。

增量不是"少算一点"——它算出来的结果和全量**逐项完全一致**（实测温度、原始口径、
六个分项全部相同）。它自己处理复权：拆股/分红会让数据源改写整段历史的复权价，
此时本地旧行与新行不在同一刻度上，硬拼会在接缝处造出一根凭空的涨跌幅；
所以每次都比对重叠区间，对不上的个股当次自动退回全量重拉（每天通常只有几只）。
另外距上次全量超过 30 天会自动强制全量一次。**所以一直用 `--fast` 是安全的。**

`daily_refresh.py` 依次做五件事：拉标普500量价与EPS → 刷新VIX与国债收益率 →
重算温度与预警 → 渲染 dashboard.html → 检查是否有新触发的预警。
全新机器上首次运行约 2–3 分钟（要下载十年历史），之后每天约 30–60 秒。

`dashboard.html` 是**完全自包含的单文件**：数据直接嵌在里面，没有外部
JS/CSS 依赖（只有一个 Google Fonts 链接，断网时自动退回系统字体）。
双击就能看，可以随便拷贝、发邮件、放U盘。

## 四、让它每天自动更新

### 方案 A：自己的电脑 / 服务器（最简单）

macOS / Linux，`crontab -e` 加一行（每天美东早八点，按你所在时区换算）：

```
0 8 * * 1-5 cd /path/to/us-sentiment && /usr/bin/python3 daily_refresh.py >> run.log 2>&1
```

Windows 用「任务计划程序」建一个每日任务，操作填 `python.exe`，参数填
`daily_refresh.py`，起始位置填项目目录。

电脑关机那天就不更新，但下次开机跑一次会自动补上（脚本按交易日判重，不会重复报警）。

### 方案 B：GitHub Actions + GitHub Pages（免费、不用自己开机）

**已经配好了**，就是 `.github/workflows/daily.yml`。它做四件事：

1. 取回缓存的 `raw/` → 跑 `daily_refresh.py --fast` → 重算温度 → 渲染 `dashboard.html`
2. 把 `data.json` / `dashboard.html` / `_pipeline_state.json` 提交回仓库
3. 把 `dashboard.html` 作为 `index.html` 发布到 GitHub Pages
4. 在 Actions 的运行摘要里贴出日志尾部（含 `NEWLY_TRIGGERED` 那一行）

三种触发方式：**工作日 12:00 UTC**（美东早8点/冬令时早7点）、**每次 push 到 main**
（改完引擎不用手动跑任何东西，页面自动重建）、以及手动触发（可勾选「全量重下十年历史」）。

**首次启用需要点一下**：仓库 Settings → Pages → Source 选 **GitHub Actions**。
只有这一步必须在网页上做，之后再也不用管。

几个容易踩的坑，都已经在 workflow 里处理掉了，改动时别踩回去：

| 坑 | 处理 |
|---|---|
| `raw/` 43MB、每天重写全部 CSV，提交进 git 会让历史无限膨胀 | 用 `actions/cache`，不进 git |
| `actions/cache` 的 key 不可变，固定 key 会让缓存永远停在第一天 | key 带 `run_id` 轮换 + `restore-keys` 前缀回退 |
| `setup-python` 的 `cache: pip` 需要 `requirements.txt`，本仓库没有 | 不开 pip 缓存（依赖就三个，装起来很快） |
| `_pipeline_state.json` 在仓库根目录而非 `raw/` 里，不持久化会导致每次都误判成「新交易日」并重复报警 | 提交回仓库 |
| 抓取失败会让整页变陈 | 抓取步骤 `continue-on-error`，失败时退回用缓存的 `raw/` 重新渲染，并在摘要里显式告警 |
| `grep ... \| tail -1` 的退出码来自 `tail`（恒为 0），`\|\| 默认值` 永不触发 | 显式判空 |

**已知风险**：`stockanalysis.com` 会不会屏蔽 Actions 的出口 IP（Azure 网段）尚未验证过。
真被挡了，退路是仓库里留着的 `fetch_sp500_yahoo.py`，或改用 Stooq / FRED（见第三节）。

### 邮件/推送提醒

`daily_refresh.py` 的标准输出最后一行固定是
`NEWLY_TRIGGERED:none` 或 `NEWLY_TRIGGERED:hot,cold,cold_soft,hot_bear,crowd,narrow`。
任何脚本都能抓这一行来决定要不要发通知，比如：

```bash
OUT=$(python3 daily_refresh.py)
echo "$OUT" | grep -q "NEWLY_TRIGGERED:none" || echo "$OUT" | mail -s "情绪温度计有新预警" you@example.com
```

GitHub Actions 里可以接 issue、Slack webhook、或者 Server酱之类的微信推送。

## 五、五条预警规则速查

| 记号 | 名称 | 条件 |
|---|---|---|
| ● 红点 | 红点预警 | **红点温度 > 75**，连续3日 |
| ○ 空心红 | 熊市反弹预警 | 跌破下行的200日均线 且 蓝点温度 > 60，连续3日 |
| ● 蓝点 | 蓝点预警 | 蓝点温度（当日口径）< 25 且 VIX ≥ 30，当日触发 |
| ○ 空心蓝 | 空心蓝点 | 同上，但处于**实际利率快速抬升期**（10年期TIPS实际利率的6个月变动 > 自身过去3年的85分位，且名义10年期国债同向上行，带滞回） |
| ▢ 黑框 | 黑框预警 | TOP2行业成交额占比 > 80分位 且 上涨拥挤度 > 75，连续3日 |

**实心 = 标准信号，空心 = 需要打折的信号。**

空心蓝点判的是"跌的原因还没结束"：蓝点只对**冲击式**下跌有效（跌得快、VIX 炸、几周内跌完），
而 2022 年那种由实际利率抬升驱动的估值重估，问题在分母不在分子，情绪指标再低也没用。

判据看的是**抬升速度**而不是水位高低，这一条 2026-09 改过一次，理由值得记住：
旧口径是"实际利率 < 0.5% 且 6 个月上行 > 0.25pp"。0.5% 是零利率年代的刻度，
实际利率涨到 2.6% 之后这条闸门**永远不可能再成立**，等于一个装饰品。
但换成绝对涨幅门槛也不行——"快"这把尺子自己跨年漂移好几倍（2018 年 6 个月变动最大 +0.44，
2022 年中位数就有 +1.03），任何单一绝对门槛要么把 2025-04、2026-03 这种好蓝点打成空心，
要么漏掉 2022 年一多半的坏蓝点。所以改成**相对速度**：跟它自己过去 3 年比。

名义同向那一条不是装饰：实际利率上行有两种成因，只有一种算重估。2020 年 3 月疫情底，
实际利率 6 个月 +0.40（分位爆表），但名义 10 年期是 −0.97——涨的原因是通胀预期崩塌，
不是紧缩。没有这条闸门，史上最好的蓝点之一会被判反。

实测（2017-10 至今 42 个蓝点日，触发后 3 个月纳指）：
**14 个空心日 −7.6%／93% 为负，28 个实心日 +28.2%／0% 为负**。
参数是一整片平坦区：分位窗口 2/3/4/5 年 × 门槛 75~95 的整片区域分组结果完全一致。
**但这个宏观状态在样本里只出现过一次（2021下半年–2022），等于零样本外验证**——
换口径并没有增加事件数，所以它只把蓝点降级为分批/半仓，不屏蔽。

### 两个温度

页面上只有两个温度，各对应一个信号：

```
红点温度 = TOP2抱团×2 + 杠杆温度×2 + 上涨拥挤度×3 + 站上MA20×1 + 换手率×1   （权重归一）
蓝点温度 = 换手率、TOP2抱团、上涨个股占比、站上MA20、杠杆多空比、风险溢价  六项等权
```

**页面顶部显示的是红点温度**，蓝点温度并列在它下方。蓝点看蓝点温度的*当日不平滑口径*
（换手率、上涨占比、杠杆多空比取当日值），熊市反弹看它的平滑口径。

两个温度分开算，是因为实测标顶和标底靠的不是同一批因子：判别力最强的上涨拥挤度（秩相关 −0.348，
是第二名的两倍多）原先不在蓝点温度里，而上涨占比与站上MA20 相关 0.84、是同一个东西量两遍
却占掉蓝点温度方差的 38%。

红点实测（触发后 3 个月纳指，基准 +5.2%／26%为负）：**23段/66天，日均 −3.34%／70% 为负**，
六次历史真顶全部命中。分年分布：2018年8天、2019年3天、2020年19天、2021年13天、2024年12天、
2025年2天、2026年9天。门槛 72/73/75/78/80 全段表现一致，不是卡在某个值上。

**必读的折扣**：减仓侧的边际在样本后半段衰减——2017–2021 是 −5.33%（该段基准 +5.70%）；
2022–2026 是 +0.38%（基准 +4.68%）。优势从 11.0 个百分点缩到 4.3 个。方向仍然一致，
但**别按全样本数字设仓位**。段间标准误约 ±1.4 个百分点，差 1 个百分点以内的数字不要当真。
加仓侧（蓝点）两段都稳（+24.5%／+21.6%，0–6%为负），比减仓侧可靠得多。

每条规则的取值理由、回测数据与试过但放弃的方案，都写在 `engine.py` 与 `leverage.py` 的注释里。
那些注释是这套东西最值钱的部分——它们记录了什么试过、什么没用、为什么。别删。

## 六、杠杆温度

口径参照 J.P. Morgan《Flows & Liquidity: Has investors leveraged peaked?》(2026-06-24)
对散户杠杆的测量思路。研报量的是杠杆ETF的资金流，免费源拿不到日频份额数据，这里改用成交额，
拆成两个可观测的维度：

```
杠杆温度 = 多空比分位 × 3 + 交易强度分位 × 1        （252日滚动分位，权重归一）
          （做多占杠杆ETF成交额）（杠杆ETF成交额 ÷ SPY+QQQ成交额）
```

方向是主项，强度负责**否决**：多空比爆表但没人真往杠杆产品里砸钱时，把读数压下去。
典型例子是 2025-09-12——多空比 99.8 分位、强度 0.2 分位，合成后 74.9，进不了红点；
那次后续 3 个月 +6.8%，减仓是错的。

十分位表说明它只在最热的一档有用：最高十分位后续 3 个月 **−0.4%／46% 为负**（基准 +5.2%／26%），
其余九档在 +4.9% ~ +7.6% 之间没有单调性。**当极端读数报警器用，别当连续打分用。**

试过并放弃的（`leverage.py` 里有实测数字，别再试第二遍）：对冲基金杠杆（HDG 波动率比）、
银行杠杆（IAI 波动率比）分位口径下符号翻正；风险平价隐含杠杆（RPAR）曲线复刻得准但秩相关是
+0.000；保证金净借款（FINRA）的 WAF 按云厂商 IP 段封，CI 上实测全 403，只能手工下载。

## 七、一句提醒

这是个观察工具，不是交易系统。所有回测都是同一段历史上做出来的，
样本只有 2017 年至今、九次蓝点、一次真正的加息周期。
网页上「已知局限」那一栏不是免责声明，是使用说明——用之前先读一遍。
