# 美股情绪温度计 — 离线运行包

这个项目**不依赖 Claude、不依赖任何大模型、不需要 API key**。
整条流水线是纯 Python + pandas/numpy，数据全部来自公开免费端点。
只要你的机器能跑 Python、能上网，它就能一直跑下去。

---

## 一、五分钟跑起来

```bash
# 1. 装依赖（只有三个）
pip install pandas numpy scipy

# 2. 跑一次完整流程
python3 daily_refresh.py          # 首次用这个（全量）
python3 daily_refresh.py --fast   # 以后日常用这个（增量，快 10 倍以上）

# 3. 用浏览器打开生成的 dashboard.html
```

**全量 vs 增量**：全量每只票重下 10 年日线，531 只 ≈ 134MB，跨境链路上要十分钟；
增量只下最近半年再并回本地，约 7MB，通常几十秒。

增量不是"少算一点"——它算出来的结果和全量**逐项完全一致**（实测温度、原始口径、
六个分项全部相同）。它自己处理复权：拆股/分红会让数据源改写整段历史的复权价，
此时本地旧行与新行不在同一刻度上，硬拼会在接缝处造出一根凭空的涨跌幅；
所以每次都比对重叠区间，对不上的个股当次自动退回全量重拉（每天通常只有几只）。
另外距上次全量超过 30 天会自动强制全量一次。**所以一直用 `--fast` 是安全的。**

`daily_refresh.py` 依次做五件事：拉标普500量价与EPS → 刷新VIX与国债收益率 →
重算温度与预警 → 渲染 dashboard.html → 检查是否有新触发的预警。
全新机器上首次运行约 2–3 分钟（要下载十年历史），之后每天约 30–60 秒。

`dashboard.html` 是**完全自包含的单文件**：数据直接嵌在里面，没有外部
JS/CSS 依赖（只有一个 Google Fonts 链接，断网时自动退回系统字体）。
双击就能看，可以随便拷贝、发邮件、放U盘。

每个都有注释说明取值理由、扫描过的备选值，以及**试过但放弃的方案和放弃的原因**。

## 四、让它每天自动更新

### 方案 A：自己的电脑 / 服务器（最简单）

macOS / Linux，`crontab -e` 加一行（每天美东早八点，按你所在时区换算）：

```
0 8 * * 1-5 cd /path/to/us-sentiment && /usr/bin/python3 daily_refresh.py >> run.log 2>&1
```

Windows 用「任务计划程序」建一个每日任务，操作填 `python.exe`，参数填
`daily_refresh.py`，起始位置填项目目录。

电脑关机那天就不更新，但下次开机跑一次会自动补上（脚本按交易日判重，不会重复报警）。

### 方案 B：GitHub Actions + GitHub Pages（免费、不用自己开机）

**已经配好了**，就是 `.github/workflows/daily.yml`。它做四件事：

1. 取回缓存的 `raw/` → 跑 `daily_refresh.py --fast` → 重算温度 → 渲染 `dashboard.html`
2. 把 `data.json` / `dashboard.html` / `_pipeline_state.json` 提交回仓库
3. 把 `dashboard.html` 作为 `index.html` 发布到 GitHub Pages
4. 在 Actions 的运行摘要里贴出日志尾部（含 `NEWLY_TRIGGERED` 那一行）

三种触发方式：**工作日 12:00 UTC**（美东早8点/冬令时早7点）、**每次 push 到 main**
（改完引擎不用手动跑任何东西，页面自动重建）、以及手动触发（可勾选「全量重下十年历史」）。

**首次启用需要点一下**：仓库 Settings → Pages → Source 选 **GitHub Actions**。
只有这一步必须在网页上做，之后再也不用管。

几个容易踩的坑，都已经在 workflow 里处理掉了，改动时别踩回去：

| 坑 | 处理 |
|---|---|
| `raw/` 43MB、每天重写全部 CSV，提交进 git 会让历史无限膨胀 | 用 `actions/cache`，不进 git |
| `actions/cache` 的 key 不可变，固定 key 会让缓存永远停在第一天 | key 带 `run_id` 轮换 + `restore-keys` 前缀回退 |
| `setup-python` 的 `cache: pip` 需要 `requirements.txt`，本仓库没有 | 不开 pip 缓存（依赖就三个，装起来很快） |
| `_pipeline_state.json` 在仓库根目录而非 `raw/` 里，不持久化会导致每次都误判成「新交易日」并重复报警 | 提交回仓库 |
| 抓取失败会让整页变陈 | 抓取步骤 `continue-on-error`，失败时退回用缓存的 `raw/` 重新渲染，并在摘要里显式告警 |
| `grep ... \| tail -1` 的退出码来自 `tail`（恒为 0），`\|\| 默认值` 永不触发 | 显式判空 |

**已知风险**：`stockanalysis.com` 会不会屏蔽 Actions 的出口 IP（Azure 网段）尚未验证过。
真被挡了，退路是仓库里留着的 `fetch_sp500_yahoo.py`，或改用 Stooq / FRED（见第三节）。

### 邮件/推送提醒

`daily_refresh.py` 的标准输出最后一行固定是
`NEWLY_TRIGGERED:none` 或 `NEWLY_TRIGGERED:hot,cold,cold_soft,hot_bear,crowd,narrow`。
任何脚本都能抓这一行来决定要不要发通知，比如：

```bash
OUT=$(python3 daily_refresh.py)
echo "$OUT" | grep -q "NEWLY_TRIGGERED:none" || echo "$OUT" | mail -s "情绪温度计有新预警" you@example.com
```

GitHub Actions 里可以接 issue、Slack webhook、或者 Server酱之类的微信推送。

## 五、六条预警规则速查

| 记号 | 名称 | 条件 |
|---|---|---|
| ● 红点 | 红点预警 | **减仓温度 > 75**，连续3日 |
| ○ 空心红 | 熊市反弹预警 | 跌破下行的200日均线 且 综合温度 > 60，连续3日 |
| ● 蓝点 | 蓝点预警 | 快口径温度 < 25 且 VIX ≥ 25，当日触发 |
| ○ 空心蓝 | 空心蓝点 | 同上，但处于贴现率重估状态（10年期TIPS < 0.5% 且6个月上行 > 0.25pp，带滞回） |
| ▢ 黑框 | 黑框预警 | TOP2行业成交额占比 > 85分位 且 杠杆多空比 > 75分位，连续3日 |
| ▬ 橙线 | 橙线预警 | 窄幅逼空评分 > 75，连续3日（纳指走势线本身染成橙色） |

### 两个温度，各管一头

页面顶部的**综合温度**（六项等权）负责*描述*市场状态；红点改用单独加权的**减仓温度**负责*标顶*：

```
减仓温度 = TOP2抱团×2 + 杠杆温度×2 + 窄幅逼空×3 + 站上MA20×1 + 换手率×1   （权重归一）
```

拆开的原因是实测：标顶和标底靠的不是同一批因子。原先的红点（综合温度>80）是四个减仓信号里最弱的
一个，触发后 3 个月 +3.2%／34%为负（基准 +5.2%／27%），还不如黑框和橙线；而判别力最强的窄幅逼空
评分（秩相关 −0.348，是第二名的两倍多）当时根本不在温度里，上涨占比与站上MA20 相关 0.84、是同一个
东西量两遍却占掉温度方差的 38%。

2026-09 又动了一处：杠杆那一格从「杠杆多空比」单项换成了**杠杆温度**（多空比与杠杆ETF交易强度各半，
见第六节）。三代红点的实测对照（触发后 3 个月纳指，基准 +5.2%／26%为负）：

| 红点口径 | 段数/天数 | 段均+63日 | 日均+63日 | 为负 | 2017–2021 | 2022–2026 | 六次真顶 |
|---|---|---|---|---|---|---|---|
| 综合温度 > 80（最初） | 18段/56天 | — | +3.18% | 34% | — | — | — |
| 减仓温度，杠杆＝纯多空比 | 26段/81天 | −1.85% | −1.79% | 59% | −5.40% | **+2.49%** | 6/6 |
| 减仓温度，杠杆温度 1:1（曾用两周） | 16段/63天 | −1.55% | −2.75% | 68% | −4.63% | −0.38% | **4/6** |
| 减仓温度，杠杆温度 **3:1**（现行） | 23段/66天 | **−2.39%** | **−3.34%** | **70%** | −5.33% | +0.38% | 6/6 |

分年分布：2018年8天、2019年3天、2020年19天、2021年13天、2024年12天、2025年2天、2026年9天
（对照最初口径：2021泡沫顶 0 天、2023熊市后 21 天，全样本最多）。

**曾经把权重取错过**：第一版杠杆温度取 1:1，依据是"这个因子自己的秩相关两段都稳"。
上线后 2018-08-28~30 与 2019-12 两段红点消失了——那是全样本最值钱的两次（触发后 3 个月
−11.3% 与 −15.4%）。原因不是强度腿否决了它们，那几天两条腿都高（2018-08-28：多空比 82.7、
强度 71.6），是**两个分位取平均把读数向 50 压缩**，减仓温度刚好滑到门槛 75 以下。
**换了分项却不重标门槛，等于把红点悄悄调严**（81天→63天）。改成 3:1 后两段都回来了，
而 2025 年秋天那批该否决的（强度 0.2~13 分位、后续 3 个月 +6.8%/+4.5%/+2.7%）仍被挡住：
12 天降到 2 天。教训写在 `leverage.py` 的 `LEV_W` 注释里——**选权重要看信号的实际表现，
不是看因子自身的秩相关**。

**必读的折扣**：减仓侧的边际在样本后半段仍然衰减——2017–2021 是 −5.33%（该段基准 +5.70%）；
2022–2026 是 +0.38%（基准 +4.68%）。优势从 11.0 个百分点缩到 4.3 个。方向仍然一致，
但**别按全样本数字设仓位**。另外段均那一列的段间标准误约 ±1.4 个百分点，
表里差 1 个百分点以内的行不要据此排序。
加仓侧（蓝点）两段都稳（+24.5%／+21.6%，0–6%为负），比减仓侧可靠得多。

**实心 = 标准信号，空心 = 需要打折的信号。**
每条规则的取值理由、回测数据和已知局限，都写在网页的「已知局限」区块和 `engine.py` 的注释里。
那些注释是这套东西最值钱的部分——它们记录了什么试过、什么没用、为什么。别删。

## 六、杠杆温度（按研报口径重建）

参照 J.P. Morgan《Flows & Liquidity: Has investors leveraged peaked?》(2026-06-24)。
研报的做法不是"找一个杠杆指标"，而是**按持有人分层**，每层各用一个可观测的代理量。
这里逐条对照，只保留免费可得的：

| 研报 | 层 | 研报的口径 | 本仓库怎么做 |
|---|---|---|---|
| Fig 1/2 | 散户 | 杠杆ETF的资金流与再平衡流 | **进温度**：杠杆ETF成交额的多空比 + 交易强度 |
| Fig 3 | 散户 | OCC 小单（<10张）看涨期权净买入 | 放弃：无免费日频源 |
| Fig 4 | 散户 | NYSE 保证金净借款 ÷ 标普500市值 | 只展示：FINRA 月频，可选（见下） |
| Fig 5 | 对冲基金 | 基金收益波动率 ÷ 标的波动率 | 试过 HDG 替代，**放弃**（分位口径下符号翻正） |
| Fig 6 | 风险平价 | 基金收益波动率 ÷ 风险平价基准波动率 | 只展示：RPAR ÷ 固定权重基准 |
| Fig 7 | 银行 | 交易利润波动率 ÷ 资产波动率 | 试过 IAI 替代，**放弃**（同上） |
| Fig 8/9 | 企业/家庭 | 债务占GDP、净利息占经营现金流 | 不做：季频慢变量，研报自己的结论是"不构成脆弱性" |

```
杠杆温度 = 杠杆ETF多空比分位 × 3 + 杠杆ETF交易强度分位 × 1      （252日滚动分位，权重归一）
          （做多占杠杆ETF成交额）  （杠杆ETF成交额 ÷ SPY+QQQ成交额）
```
方向腿是主角，强度腿的作用是**否决**：多空比爆表但没人真往杠杆产品里挤钱时，把读数压下去。

**为什么要补第二条腿**：原来只看多空比，它只量*方向*不量*强度*。对未来 63 日纳指的秩相关，
2017-10~2021-12 是 −0.407，2022-01~2026-09 变成 **+0.062**——符号都反了，这正是减仓信号后段
衰减的主要来源。典型病例是 2023-06-14：多空比原始 66.0%，对比过去一年读到 **99.8 分位**（"十年最热"），
而同一天真正挤进杠杆产品的钱少得可怜——交易强度分位只有 **3.0**。两项合成后当天读 51.4，
而 2021-11-19 泡沫顶两项都在 96 以上。3:1 合成后，2023-06-14 读 75.6（全年 ≥80 分位的天数从 141 天降到 13 天），泡沫顶 2021-11-19 仍读 98.9。

十分位表也说明它只在最热的那一档有用：最高十分位后续 3 个月 **−0.40%／46%为负**（基准 +5.2%／26%），
其余九档都在 +4.9% ~ +7.6% 之间没有单调性。**把它当"极端读数报警器"用，别当连续打分用。**

**另外两把尺，只描述不进温度**：
- *风险平价隐含杠杆* = σ63(RPAR) ÷ σ63(无杠杆基准)，基准按 RPAR 目标配置 SPY 25/TIP 35/TLT 35/GLD 10/DBC 15
  归一到 100%。这条线复刻得相当准——峰值落在 **2026-05-20**，与研报说的"mid-May 创十年新高"对得上，
  之后回落也对得上"recent weeks 在退"。但它的分位对未来收益秩相关是 **+0.000**，进温度只会稀释，故只展示。
- *保证金净借款*（研报 Fig 4 的主尺）= 融资借方余额 − 现金账户贷方 − 融资账户贷方。月频、次月第 3~4 周才发布，
  代码里按 25 个自然日模拟发布滞后（不做就是前视）。

**研报那句"见顶回落是利空"没能验证**：把"63 日内峰值≥阈值、当前回落≥D、温度仍在高位"写成事件规则，
扫了 12 组参数，触发后 63 日收益全部落在 +4.3% ~ +5.0%，基准是 +5.18%——没有边际。
反倒是**维持高位**有区分度（温度≥85 且仍贴近 63 日峰值：+1.95%／33%为负）。
所以这里输出的是**水平温度**，不是拐点信号；页面上把"较峰值回落多少"作为描述列出，但不拿它触发任何预警。

### 打开保证金那一项（可选，**只能在自己机器上跑**）

美元）、跨度、新鲜度三关，不合格**直接拒绝写文件**。解析与校验这部分有测试覆盖
（`test_engine.py` 第 17 组），没覆盖的只有"那个 URL 今天还对不对"。

`raw/` 整体不进 git，但 `raw/_margin.csv` 开了例外（几 KB、每月只变一行；而且它是唯一一个
**重算不出来、只能下载**的输入，FINRA 只挂当期文件，漏一个月就补不回来）。

文件不在时，页面上少一行读数，**温度与全部预警不受任何影响**。
